# EN .REC — Project Context for Website Build

## 1. Qué es EN .REC

EN .REC es una productora audiovisual y plataforma de música en vivo.

El proyecto registra artistas en sesiones en vivo filmadas en locaciones únicas, buscando que cada sesión refleje el universo sonoro, visual y emocional del artista.

No es solo un canal de sesiones: EN .REC funciona como una plataforma cultural que combina:
- sesiones en vivo
- curaduría musical
- contenido sobre artistas
- backstage
- entrevistas breves
- piezas audiovisuales para redes
- construcción de comunidad alrededor de la música en vivo

Lema / frase de marca:
**“Lo que ves, lo que suena.”**

## 2. Posicionamiento

EN .REC busca diferenciarse de otros canales de sesiones por:

- Dirección artística personalizada para cada artista
- Locaciones con identidad, no escenarios genéricos
- Alta calidad audiovisual
- Curaduría musical cuidada
- Estética visual fuerte
- Cercanía con la escena musical independiente / alternativa / pop indie
- Contenido pensado tanto para el artista como para su audiencia
- Una experiencia audiovisual completa, no solo una grabación

La idea central:
> Cada sesión tiene que sentirse como una pieza única del universo del artista.

## 3. Tono de marca

El tono debe ser:
- cercano
- cool
- claro
- sensible pero no cursi
- cultural pero no pretencioso
- moderno
- directo
- con identidad

Evitar:
- frases demasiado genéricas
- tono institucional frío
- exceso de solemnidad
- frases tipo “muy pronto”
- copy demasiado largo
- lenguaje corporativo

Ejemplos de tono:
- “Un espacio, una canción, una forma de mirar.”
- “Sesiones en vivo pensadas desde el sonido, la imagen y el universo de cada artista.”
- “Registramos música en vivo en escenarios que también cuentan algo.”
- “Lo que ves, lo que suena.”

## 4. Público objetivo

Audiencia principal:
- Personas de 18 a 34 años
- Argentina, principalmente CABA, GBA, Rosario y Córdoba
- También puede interesar en México, Chile, Colombia y España
- Interesados en música indie, pop indie, indie latino, folk pop y nuevas escenas

Referencias musicales de audiencia:
- Zoe Gotusso
- Silvina Moreno
- Natalia Lafourcade
- Julieta Venegas
- Clara Cava
- Silvana Estrada
- LOUTA en su costado más suave
- artistas independientes latinoamericanos

## 5. Identidad visual

La web debe sentirse:
- audiovisual
- editorial
- artística
- moderna
- minimalista pero con carácter
- enfocada en imagen/video
- con mucho peso visual en thumbnails, stills y frames de sesiones

Referencias visuales:
- feed cuidado
- estética cinematográfica
- contraste entre espacios vacíos, artistas y detalles
- uso de rojo EN .REC como color principal de marca
- tipografía fuerte para títulos
- diseño limpio, no sobrecargado

El sitio debe priorizar:
- video
- imagen grande
- grillas limpias
- buena experiencia mobile
- estética de plataforma cultural

### Radar EN .REC / Convocatoria

Una forma de descubrir artistas y darles la posibilidad de grabar una sesión en vivo con EN .REC.

Copy posible:
“Buscamos nuevos proyectos para grabar una sesión en vivo con EN .REC.”

Premio:
- Grabación de una sesión en vivo
- Producción audiovisual
- Publicación en el canal de EN .REC
- Clips para redes

Condiciones posibles:
- Proyecto musical activo, solista o banda

- Contar con registro audiovisual en vivo

- Redes sociales activas

- La selección queda a criterio curatorial de EN .REC
- Puede haber finalistas y/o instancia de voto público, pero la curaduría final la define EN .REC

Campos del formulario:
- Nombre del proyecto
- Integrantes
- Ciudad / zona
- Género musical

## 7. Derechos y lógica de publicación

Modelo habitual:
- El videograma pertenece a EN .REC
- El fonograma puede quedar en manos del artista, sello o titulares correspondientes
- EN .REC solicita autorización para usar el audio dentro del video publicado en su canal
- Puede evaluarse publicación colaborativa con el artista
- La monetización de YouTube puede acordarse por contrato, eventualmente 50/50 según caso
- Si hay sello discográfico, se puede adaptar la propuesta para que el fonograma quede en el sello, manteniendo el videograma en EN .REC

## 10. Sesiones y métricas conocidas

Hasta mayo de 2025 tenía:
- 5 sesiones publicadas

- alrededor de 550 seguidores en Instagram

Luego, con pauta, creció a:
- aproximadamente 770 suscriptores en YouTube
- aproximadamente 720 seguidores en Instagram

Para 2026 el proyecto ya venía con una estética más consolidada y una comunidad más activa.

## 15. Infraestructura real de producción

### Servidor

El sitio corre en un **Proxmox VE** con un **LXC Container (CT 4100)**.

- Host Proxmox: `100.66.210.79` — usuario `root` — contraseña `Panama26+`
- Para ejecutar comandos dentro del CT se usa `pct exec`:

```bash
# Conectar al host Proxmox
sshpass -p 'Panama26+' ssh -o StrictHostKeyChecking=no root@100.66.210.79 '...'

# Ejecutar dentro del CT 4100 (SIEMPRE usar bash -lc para cargar PATH/nvm/node)
pct exec 4100 -- bash -lc "comando aquí"
```

**IMPORTANTE:** Usar `bash -lc` (login shell), NO `bash -c`. Sin el `-l` no se carga el PATH de node/npm/pnpm y los comandos fallan con "command not found".

### Directorio del proyecto en el CT

```
/home/sites/enrec/          ← raíz del repo
/home/sites/enrec/dist/     ← frontend compilado (servido por nginx)
/home/sites/enrec/backend/  ← NestJS backend
```

### Proceso PM2

- Nombre: `enrec-backend`
- ID PM2: `13`
- Comando de restart: `pm2 restart enrec-backend`

### Comandos de deploy

**Solo frontend** (sin cambios de backend):
```bash
sshpass -p 'Panama26+' ssh -o StrictHostKeyChecking=no root@100.66.210.79 \
  'pct exec 4100 -- bash -lc "cd /home/sites/enrec && git pull && pnpm build"'
```

**Frontend + backend** (cuando hay cambios en `/backend`):
```bash
sshpass -p 'Panama26+' ssh -o StrictHostKeyChecking=no root@100.66.210.79 \
  'pct exec 4100 -- bash -lc "cd /home/sites/enrec && git pull && pnpm build && cd backend && npm run build && pm2 restart enrec-backend"'
```

**Flujo completo de deploy desde local:**
1. `git add ... && git commit -m "..."` — commitear cambios
2. `git push` — subir a GitHub (repo: `SwitchIT-AR/enrec`)
3. Ejecutar el comando SSH de arriba según corresponda

### Variables de entorno del backend

Están en `/home/sites/enrec/backend/.env` dentro del CT. Incluyen:
- `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` — PostgreSQL local
- `ADMIN_TOKEN` — token para el panel `/admin`
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_SECURE` — email
- `FROM_NAME`, `FROM_EMAIL`, `NOTIFY_EMAIL` — configuración de emails
- `YOUTUBE_API_KEY` — YouTube Data API v3
- `ENREC_CHANNEL_ID` — canal de YouTube de EN .REC

### Stack real en producción

- **Frontend:** React 19 + Vite 7 + TypeScript + Mantine + CSS Modules
- **Backend:** NestJS v10 + TypeORM + PostgreSQL (`synchronize: true`)
- **Process manager:** PM2
- **Web server:** nginx (sirve `dist/` y hace proxy al backend en `/api/`)
- **Node en el CT:** instalado vía nvm (por eso requiere login shell)
